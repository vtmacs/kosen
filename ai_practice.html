🤖 さくらのAI Engine をコマンドで動かす

授業で使うコマンドを、コピー＆ペーストで試せる手順書です。上から順に、ターミナルに貼り付けて実行してください。

0準備：ターミナルと道具を確認する

0.1jq と curl が使えるか確認

ターミナルを開いて、次のコマンドを実行します。どちらもバージョンが表示されればOKです。

💡 command not found と出たら、講師に声をかけてください。
0.2アカウントトークンを入力（このページだけで使います）
配られたアカウントトークン（UUID:シークレット の形）を入力すると、下のコマンドに自動で入ります。
💡 入力したトークンはこのページの中だけで使われ、保存も送信もされません。画面に表示されるコマンドでは一部を「•」で隠しています（コピーすると本物が入ります）。人に見せたり、SNSに貼ったりしないでください。
1トークンを環境変数に入れる
1.1環境変数 AI_ENGINE_TOKEN をつくる
トークンを環境変数に入れます。以降のコマンドは、この変数を使います。
💡 環境変数はターミナルごとに別です。新しいターミナルを開いたら、もう一度実行してください。
1.2入ったか確認する
トークンが表示されればOKです。何も表示されなければ、1.1 をやり直します。
2ハンズオン①：curl でAIに質問する
2.1AIに質問して、返ってきたJSONを見る
chat/completions にJSONを送ります。最後の | jq . で、1行で返ってくるJSONを見やすく整形します。
💡 choices[0].message.content に答えが、usage に使ったトークン数が入っています。
2.2答えの文だけを取り出す
最後の jq を -r '.choices[0].message.content' にすると、答えの文だけが表示されます。
2.3役割（system）と質問を書き換えて再実行する
system でAIの役割を決められます。入力欄を書き換えると、コマンドも変わります。
💡 質問のうしろに「箇条書きで」「100字以内で」「小学生にもわかるように」と書き足すと、答え方が変わります。
2.4（発展）結果をファイルに保存して jq で調べる
リダイレクト（>）で保存しておけば、jq で何度でも調べられます。
💡 max_tokens を小さくすると、finish_reason が length（途中で切れた）になります。
2.5（発展）Python から呼び出す
次のコマンドで chat.py を作って実行します。URL・ヘッダ・データを渡すのは curl と同じです。
💡 ModuleNotFoundError: requests と出たら pip install requests を実行してから、もう一度 python3 chat.py。
3ハンズオン②：RAG を動かす
3.1RAGなしで質問する
まずはハンズオン①と同じAPIで、資料の内容について聞きます。答えをメモしておきます。
💡 AIは「さくら高専 学生寮のしおり」を読んでいないので、知らないと答えるか、それっぽい作り話をします。
3.2RAGありで同じ質問をする
エンドポイントが documents/chat/ に変わり、質問は query に書きます。
💡 3.1 の答えと見比べます。threshold を大きくすると遠い資料まで使い（ゆるい）、小さくすると近い資料だけ使います（厳しい）。
3.3参照した資料を見る
最後の jq を .sources にすると、AIが根拠にした資料の部分が見えます。
3.4資料にないことを聞いて、比べる
💡 RAGは「登録した資料の範囲でしか根拠を持てない」ことを確かめます。3つの答え（RAGなし・RAGあり・資料にない質問）の違いを1文で書いてみましょう。
？うまくいかないとき


401 Unauthorized ／ Invalid token
  • echo $AI_ENGINE_TOKEN で中身を確認
  • そのターミナルで 1.1 を実行したか
  • 前後によけいな空白がないか


コマンドが終わらない（> が出る）
  • Ctrl+C で中断
  • 引用符が全角（” ’）になっていないか
  • 行末の \ のうしろに空白がないか


つながらない ／ 応答がない
  • ネットワークにつながっているか
  • 学内ネットワークの制限がないか
