Docker & さくらのクラウドAppRun ハンズオン

1. はじめに

このハンズオンでは、クラウド上のUbuntuサーバーにDocker環境を構築し、基本的なコンテナ操作を学びます。後半では、作成したコンテナを**さくらのクラウド「AppRun」**を使って、インフラ管理不要（サーバーレス）でインターネットに公開する一連の開発フローを体験します。

本日のゴール
① 踏み台経由で実習用サーバーに接続し、DockerをインストールしてWebサーバーを立ち上げる。
② AppRunを使って、自分の名前と色を設定した「ネームボード」コンテナをデプロイし、クラス全体のボードと連携させる。

2. 踏み台サーバーへの接続

今回の実習環境はセキュリティを高めるため、直接アクセスすることができません。まずは入り口となる「踏み台サーバー」にSSH接続します。

ターミナル（WindowsはPowerShell、Macはターミナル）を開き、以下のコマンドを実行してください。

bash 
ssh -l ubuntu <踏み台サーバーIPアドレス>

パスワードを求められた場合は、教員から指示されたパスワードを入力します。（※入力中、画面に文字は表示されません）

3. Docker環境の構築

踏み台サーバーを経由して、実際にDockerを動かす実習用のUbuntuサーバーに接続し、Dockerをインストールします。

3.1 実習用サーバーへのログイン

踏み台サーバーにログインした状態のまま、続けて実習用サーバーにSSH接続します。

bash 
ssh -l ubuntu <実習用サーバーIPアドレス>
ログインの確認＆パスワード
パスワードを入力（handson-sakura）してログインした後、ターミナルの入力行（プロンプト）の表示が ubuntu@jump-host-** から ubuntu@server**（**は数字）に変わっていることを確認してください。表示が変わっていれば、実習用サーバーへの接続は成功です。

3.2 Dockerのインストール

自動インストールスクリプトをダウンロードし、実行します。

bash 
curl -fsSL https://get.docker.com -o install-docker.sh
sudo sh ./install-docker.sh

3.3 ユーザー権限の設定

現在の ubuntu ユーザーが sudo なしでDockerコマンドを実行できるように、グループに追加します。

bash 
sudo usermod -aG docker ubuntu
重要: グループ設定の反映には再ログインが必要です
設定を反映させるため、ターミナルで以下の exit コマンドを実行して一度ログアウトしてください。
bash 
exit
注意: 踏み台サーバーに戻ります
exit を実行すると、手前の踏み台サーバーに戻ります。
そのため、もう一度以下のコマンドを実行し、実習用サーバーに再ログインしてください。
bash 
ssh -l ubuntu <実習用サーバーIPアドレス>
再ログイン後の確認
3.1節の「ログインの確認＆パスワード」を参考に、実習用サーバーに再接続した後は、ターミナルの入力行（プロンプト）の表示が ubuntu@jump-host-** から ubuntu@server**（**は数字）に変わっていることを必ず確認してください。

再ログイン後、以下のコマンドを実行してDockerのバージョン情報（ClientやServerの情報）がターミナルに表示されれば準備完了です。

bash 
docker version

4. コンテナの起動実験

環境が整ったので、テスト用のコンテナを実行してみましょう。ここではコンテナを2回起動し、その後にコンテナとイメージの片付け（基本ライフサイクル）までを体験して環境を一度リセットします。

4.1 コンテナを2回起動してみる

まずは以下のコマンドを入力し、最初のコンテナを立ち上げます。

bash 
docker run hello-world
1回目の動作の特徴
最初は Unable to find image 'hello-world:latest' locally と表示されます。手元のサーバーにイメージが存在しないため、Docker Hubから自動的にダウンロード（Pull）を行っている様子を示しています。

1回目が完了したら、まったく同じコマンドを**もう一度**実行してみてください。

bash 
docker run hello-world
2回目の動作の特徴（確認事項）
2回目の実行ではダウンロード処理が入らず、**コマンドを押した瞬間に一瞬でメッセージが出力されたこと**を確認してください。すでに手元に hello-world イメージが保存（キャッシュ）されているためです。

ダウンロードされたイメージ一覧を確認してみます。

bash 
docker images

実行結果として、hello-world イメージがローカルにしっかりと保存されていることが確認できます。

4.2 実験用コンテナとイメージの片付け

次の実習に進む前に、起動した実験用コンテナとイメージを削除しておきましょう。

① まず、停止中のものも含めて、実行したすべてのコンテナの一覧を確認します。

bash 
docker ps -a

※ `hello-world` コンテナが STATUS: Exited (0) ...（停止中）としてリストに存在するはずです。また、右端にある自動付与されたコンテナ名（NAMES）を確認します。

② 確認したコンテナの「CONTAINER ID」または自動生成された「NAMES（コンテナ名）」を指定して、コンテナを完全に削除します。

bash 
docker rm <確認したコンテナ名、またはIDを入力>

※ 削除後、再度 docker ps -a を実行してリストから消えたことを確認しましょう。

③ 最後に、ローカルにダウンロードされた hello-world のイメージ自体も削除して環境を元通りにリセットします。

bash 
docker rmi hello-world

5. Apache(Webサーバー)の起動

実験環境がきれいになったところで、次は実践的なWebサーバーである「Apache」をコンテナとして立ち上げ、動作確認と削除までを行います。

5.1 Apacheイメージの取得と起動

Webサーバーソフトウェア「Apache」があらかじめ含まれている公式イメージ httpd をダウンロード（Pull）し、コンテナをバックグラウンドで起動します。

① まず、httpdイメージをダウンロードします。

bash 
docker pull httpd

② 正常にイメージが取得できたか一覧で確認します。

bash 
docker images

③ コンテナをバックグラウンド（-d オプション）で起動します。この際、ホストのポートとコンテナのポートを接続します。

bash 
docker run -d -p 8080:80 httpd

④ コンテナが正常に動作しているか確認し、自動生成された「NAMES（コンテナ名）」を確認します。

bash 
docker ps
[解説] ポート設定（-p 8080:80）の仕組み
ブラウザからコンテナのWebサービスにアクセスするには、コンテナ作成時に通信の出入り口となる「ポート」を設定する必要があります。
コマンド内の -p 8080:80 は、外部からホストサーバーの「ポート 8080」に届いたリクエストを、コンテナ側の「ポート 80 (Apacheの入り口)」へ自動転送(フォワーディング)するようつなぐ設定を行っています。

5.2 動作確認

ブラウザを開き、http://<実習用サーバーIPアドレス>:8080 にアクセスしてください。「It works!」と表示されればWebサーバーの起動に成功しています。

5.3 Apacheコンテナの停止と片付け

確認が終わったら、先ほど学んだライフサイクル管理の復習として、起動中のApacheコンテナを停止・削除し、最後にイメージも片付けます。

① バックグラウンドで起動しているApacheコンテナを安全に停止させます。

bash 
docker stop <確認したコンテナ名、またはIDを入力>

② 停止状態になったコンテナ（STATUSがExitedになっていること）を確認した後、システムから完全に削除します。

bash 
docker ps -a
docker rm <確認したコンテナ名、またはIDを入力>

③ 最後に、不要になった httpd イメージ自体も削除してディスクを整理します。

bash 
docker rmi httpd

6. さくらのクラウドAppRun ハンズオン

ここまではUbuntuサーバー上でDockerを動かしました。しかし実際のサービス運用では、「サーバーのOSアップデート」や「セキュリティ対策」などのインフラ管理が大変になります。

そこで、「コンテナイメージを渡すだけで、あとはクラウドが勝手に自動運用してくれる」というサーバーレス技術である「AppRun」を体験します。

プロジェクト: クラス・ネームボード
今回は、各自が自分の名前と好きな色を表示するコンテナをAppRunにデプロイします。デプロイされたURLを集約サイトに登録すると、教室のスクリーンに全員のボードがリアルタイムで表示されます。

7. AppRunへのデプロイ手順

7.1 コントロールパネルへログイン

ブラウザで以下のURLにアクセスし、教員から配布されたアカウント情報（会員ID、パスワード）で、さくらのクラウドコントロールパネルにログインします。

さくらのクラウド コントロールパネル ログインURL:
https://secure.sakura.ad.jp/cloud/

7.2 アプリケーションの作成

ログイン後、画面上部に表示される「さくらのクラウドホーム」画面中央の「クラウド/クラウド連携サービス」エリアに移動します。

その中にある「AppRun専用型 / AppRun共用型」と書かれた青い文字のリンクを探し、その右側の「AppRun共用型」をクリックします。遷移後のアプリケーション一覧画面で、右上の「アプリケーションを作成」ボタンをクリックします。

コントロールパネル画面には多くの設定項目が表示されますが、学生の皆さんが入力・設定するのは以下の「2つの項目」のみです。

注意: 他の項目は変更しないでください
表に記載のない項目（オートスケーリング設定、タイムアウト値、ポート設定、レジストリアクセス設定など）は、最初から入っているデフォルト値のまま決して変更しないでください。
設定項目 設定方法 / 入力値
アプリケーション名 nameboard (※任意の英数字)
※画面上部「アプリケーションの設定をしてください」エリアの一番最初に入力します。
コンテナイメージ kosen-handson.sakuracr.jp/nameboard:latest
※画面下部「コンテナの構成情報を設定してください」エリアの「コンテナ」タブ内にある最初の入力欄に入力します。

7.3 【重要】環境変数の設定（タブ切り替え）

コンテナのコードを直接書き換える代わりに、環境変数を使ってWebアプリの表示（名前や好きな色、所属するグループ名）をカスタマイズします。

設定タブ切り替えの手順
① AppRun作成画面の最下部「コンテナ構成」エリアを見ると、最初は コンテナ タブが選択されています。
② その右側にある 変数 タブ をクリックして切り替えてください。

「変数」タブに切り替えたら、設定エリアに「＋ 変数を追加」ボタンを使いながら、以下のペア（3つの設定）を追加してください。

  • キー（名前）：MY_NAME / 値：ニックネーム ※本名は入力しないこと
  • キー（名前）：MY_COLOR / 値：好きなカラーコード（例: blue、#ff9900 など）
  • キー（名前）：MY_GROUP / 値：自分の所属グループ名（例: 高専、組、班 など）

7.4 デプロイと確認

入力情報をもう一度確認し、問題がなければ最下部にある「作成する」ボタンをクリックしてデプロイを開始します。完了すると https://xxx.apprun.sakura.ne.jp という専用の「公開URL」が発行されるので、クリックして自分のネームボードが表示されるか確認してください。

7.5 親サイトへの登録

自分のAppRun URLをコピーし、クラス全員のボードが集まる「親サイト（ダッシュボード）」にアクセスして登録しましょう。

クラス・ネームボード・ダッシュボード（親サイト）のURL:
https://app-696c8387-6310-4934-af1f-7e58ed600a3c.ingress.apprun.sakura.ne.jp/

※上記のリンクをクリックして親サイトを開き、自分のAppRun URLを入力して「参加する」ボタンを押してください。教室のスクリーンにあなたのネームボードが出現します！

8. 環境の片付け

パブリッククラウド環境は、リソースを起動している間コストが発生します。ハンズオンが終了したら、無駄なリソースを消費しないように必ず片付けを行いましょう。

  1. さくらのクラウドコントロールパネルのAppRun画面を開く.
  2. 作成したアプリケーション（nameboard）を選択する.
  3. 右上または下部にある「削除」ボタンをクリックし、アプリケーションを完全に削除する.

以上で, Dockerからクラウドサーバーレスへの一連のハンズオンは終了です。お疲れ様でした！
